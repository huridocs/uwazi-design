# Review — Library bulk work, part 2, playground 95c85dda..c3950726

2026-09-21. Read-only review of the diff plus the surrounding code: thesauri store and picker, single-edit Save through the overlay, bulk edit (plan, form, review, chunked Apply, Undo), modifier-only selection, Change template, Share/Permissions, and the selection actions, dialogs and menu. No browser run and no tsc run. Findings are ranked by severity; paths are relative to `app/src/`.

## High

1. **Bulk edit and Change template delete the document of every uploaded or created entity they touch.** `utils/bulkEdit.ts:303` writes `records[id] = { typeId, metadata }`, and `utils/changeTemplate.ts:110` writes the same shape. Neither keeps `documentGroups` or `files`. For an entity from Upload PDF, those live ONLY on its overlay record (`buildRecord` puts the file there). `profileFromRecord` (`data/entityProfiles.ts:~333`) passes `base = undefined` for a created entity, so the new record resolves to `files: []`, `hasDocument: false`. Scenario: upload 3 PDFs, select them with 10 other entities, bulk-set "Tipo" (or change their template), Apply. The 3 uploads lose their PDF: the Document tab is empty and the viewer has nothing to show. Only the notification's Undo brings the files back, and that Undo is replaced by the next delete or bulk change. Seed entities are unaffected, because their files come from the base profile. `saveEntityEditAtom` does it correctly (`{ ...overlayRecord(id), typeId, metadata }`); the two bulk writers do not.

2. **Bulk edit writes one language's date or country into all four languages, over their translations.** `bulkEdit.ts:249` treats every scalar that is not `text` or `multiline` as "the same value in every language". The records say otherwise. Dates are localized prose ("July 29, 1988" / "29 de julio de 1988" / "29 juillet 1988" / "29 يوليو 1988", `data/metadata.ts:165,245,306,367`), and the country is translated ("Honduras" / "هندوراس", :242/:364). Scenario: in EN, bulk-set "Date of judgment" to "May 3, 1990" on 40 entities. Their ES, FR and AR records now all read "May 3, 1990". Country also keeps the OLD `flag` (`{ ...x, value }`), so the value "Guatemala" shows 🇭🇳 in every language. The review count reads only the edited language (`valueOf(id, f, language)`), so entities whose EN value already matched are reported as unchanged while their other three languages are still overwritten (see 12).

3. **Undoing a bulk edit or template change reverts a later publish or share of the same entity.** `atoms/entityOverlay.ts` `undoAtom`, restore branch. The check that the entity is untouched since is `records[e.id] !== e.wrote`, which looks at the RECORD only. It then sets `patched[e.id]` back to the old patch unconditionally. A later write that changes only the patch passes the check. The single-entity Share (`ShareEntityModal` `applyShare({ undoable: bulk })`, so `undoable: false` for one entity) is such a write: it neither records its own undo nor invalidates the older one. Scenario: bulk edit 50 entities, then open one of them and publish it through Share, then click Undo on the bulk edit. That entity is private again, with no message. For a template change it also restores `typeId`. The check should compare the patch identity too, the same way the share branch does with `current[e.id] === e.wrotePatch`.

## Medium

4. **Delete is committed before the bulk-form guard asks.** `components/library/selectionActions.tsx:114-121`: `doDelete` runs `deleteWithUndoAtom` first. Only the following `deselect(ids)` goes through `selectionWrite`, and with a dirty bulk form that `deselect` is held by the discard-confirm. If the user picks "Keep editing": the entities are deleted, still selected, and still in the frozen set. `getEntity` still resolves them, so the bulk form counts them and Apply writes records for deleted entities. Apply's restore Undo then replaces the delete's Undo, so the deletion can no longer be undone.

5. **Switching collection with a dirty bulk form leaves the selection behind.** `atoms/library.ts:837-850`: `selectDataSourceAtom` sets `dataSourceAtom` and clears every filter first, and only then calls `clearSelectionAtom`, which the guard holds. If the user picks "Keep editing", the Library shows the new corpus while the selection (old-corpus ids), the bar and the bulk form stay. Bulk Apply is still correct, because its corpus comes from the entities. But a footer Delete or Share now passes `corpus = dataSource` (the NEW one) with old-corpus ids: `deleteWithUndoAtom` stores them under the wrong corpus, where `applyOverlay` never looks, so the "deleted" entities stay listed in their own corpus.

6. **Nothing is selectable on touch devices.** Selection is modifier-click only now (`EntitySelectBox` is `sr-only`), and there is no long-press, context menu or `pointerType` path anywhere in `components/library`. On a phone or a keyboardless iPad no selection can be made. The phone's selection sheet (Edit, Actions…) is therefore unreachable, and so is every bulk action. The only remaining route is the sr-only checkbox, which only a screen reader or a hardware keyboard can reach.

7. **In forced-colors mode, both focus on the hidden checkbox and the selected state are invisible.** The row's focus signal (`FOCUS_RING_ON_SELECT`, and the DataTable row's `has-[…:focus-visible]:ring-2`) is a Tailwind ring, which is a `box-shadow`, and forced-colors mode removes box-shadows. The selected state is `bg-parchment` from `has-[:checked]`, and forced-colors mode replaces backgrounds too. In Windows High Contrast, tabbing onto a card's second stop shows nothing, and Space selects it with no visible change. Before 641d6f8d the visible checkbox carried both. Add an `outline` (which survives forced colors) or a `forced-colors:` variant.

8. **A previewed entity and a selected entity look identical.** `EntityCard` paints `selected ? "bg-parchment"` for the PREVIEW and `has-[:checked]:bg-parchment` for SELECTED, and there is no longer a checkbox to tell them apart. Scenario: Cmd-click 3 cards, then plain-click a fourth to preview it. Four cards are parchment and the bar says "3 selected", and the page gives no way to see which three. Delete and bulk edit then act on a set the reader cannot see.

9. **Thesaurus values are matched by label, not id, so distinct values with the same label merge.** `atoms/thesauri.ts:253` `idOf = new Map(label → id)` keeps the LAST id for a repeated label (for example an "Otros" under two groups). `choiceByLanguage` then writes that id for either choice. In bulk edit, `labelForms`, `coverageOf` and the multi `matches()` (`bulkEdit.ts:264-266`: `vids[i] === form.id || labels[i] === form.byLang[l]`) all key on the label, so "− Otros" removes both values and the coverage counts them as one.

10. **Bulk "Add value" drops the id that `addValue` returns.** `BulkEditBody.tsx:~337-345`. The match against the shown list is `toLowerCase()`, not `foldLabel`, so an unaccented or other-language spelling misses it. `addThesaurusValueAtom` then folds against the thesaurus's canonical (Spanish) labels and returns the EXISTING value, but `pick = saved.label` keeps only the Spanish label, and `saved.id` is discarded (the single-edit path passes it as `extra`). Scenario, CEJIL in EN: add "amnistia". It resolves to the existing "Amnistía", which is not a label in the EN list, so `choiceByLanguage` finds no id and writes the Spanish label, without an id, into all four languages' records. It is also tagged "New".

11. **Opening bulk edit on a large selection builds every profile during render.** `commonFields` (`bulkEdit.ts:58-63`) runs `entities.every(getEntityProfile…)` per template field. With 4,398 CEJIL entities that builds every CEJIL profile synchronously in the first render. The Relationships walk makes País hubs expensive. After that, every keystroke re-renders `BulkEditBody`, and `scalarSummary(ids, f, language)` (`BulkEditBody.tsx:251`, not memoised) reruns `getEntityProfile` + `.find` for every id and every scalar field. Also, `selected` in `LibrarySelectionDrawer` is a new array whenever `listed.ids` grows, so ticking one more entity while the form is clean recomputes `commonFields` over the whole set. This is not measured; profile it before shipping selection-of-all.

## Low

12. **Review counts disagree with what Apply writes.** The review lines and the task path's `touched` (`withRecords: false`, `bulkEdit.ts:219-233`) read the edited language only. Apply writes whenever ANY language moved. So the review can say "→ X · 0 entities" and Apply still rewrites the other languages (compounds 2). The chunked task's notification counts `entries` (records written), not the review's number.

13. **Title edits in other languages are dropped on Save.** `saveEntityEditAtom` reads only `result.titles[language]`, the UI language at Save. The form edits per-language titles, so a title changed in the FR tab while reading in EN is lost without a word. (`commitDraftAtom` falls back to other languages; this path does not.)

14. **Change template drops scalar values outside the source template without counting them.** `templateChangeRecords` rebuilds each language from the TARGET's blank list plus relationships and `description`. A scalar on the record that the SOURCE template doesn't declare (CEJIL records carry some; CLAUDE.md: "fields the template doesn't declare … go last") is dropped. `planTemplateChange` counts only source-template fields, so the review's "N values will be deleted" undercounts.

15. **Frozen sets keep deleted entities.** `BulkEditBody` and `ChangeTemplateDialog` resolve ids with `getEntity`, which still resolves deleted ids by design. A delete during an open form (see 4), or a delete-then-Undo race, leaves them in `n`, the counts and the written records.

16. **A chunked run has gaps.**
    - Its Undo is recorded only in `finish`. An exception inside `plan(chunk)` stops `step` with chunks already written and no Undo recorded, and the activity stays stuck.
    - A delete made while the task runs is replaced by the task's Undo when it finishes, even though the delete was the user's most recent action.
    - Two tasks can run at once over overlapping entities, and only the last one's Undo survives.

17. **Two Undo-guard gaps.**
    - `writeBulkChunkAtom` records `patch: before.patched[id]` per chunk, but gives every entity an empty patch `{}` when the plan has none. That means a no-op merge, but a new object. Harmless on its own; it is what makes the patch-identity check in 3 necessary.
    - The share branch's member restore compares `next[e.id] !== e.wroteMembers`. A later non-undoable single Share rewrites that array, so the restore is skipped. That is correct, but the patch half of the same entry is still restored if the patch matched, so an undo can restore visibility and skip the members for the same entity.

18. **Label folding merges some genuinely different values.** `foldLabel` (case plus accents) also merges values that are not the same: "Sí"/"Si", "CAT"/"Cat", Arabic labels differing only by harakat (`\p{M}` strips them). The editor's "Add value" then silently picks the existing one. The modal names the match, which mitigates it, but the bulk path (10) doesn't use the modal's match.

19. **A value added in one language has only that language's label.** On CEJIL, a value created while writing in EN has only its EN label. `cejilValueLabels` knows no translation, so ES, FR and AR records get the English label. The CEJIL card, which is built from the ES record, then shows English.

20. **Actions menu gaps.** `SelectionActionsMenu` has no focus-out close: Tab from the last item leaves the menu open, with its items still in the tab order behind the next control. Disabled items explain themselves only through `title`, which a keyboard user never sees. `Hint` is used for the same case elsewhere.

21. **Copy From breaks a multiselect label that contains a comma.** Copy From's multiselect path splits the source's display string on ", " (`MetadataView` `withLabels(f, sourceValue.split(", "))`). The type docs say a label can itself contain ", ", so such a value arrives as two labels.

## Checked and clean
- The guard covers every selection write: `toggle`, `range`, `selectIds`, `deselectIds` and `clear` all go through `selectionWrite`, so the keyboard paths (Space, Shift+Arrow), select-all, Escape → clear, the drawer's remove-X and Clear are all held by a dirty bulk form. The two exceptions are 4 and 5, where a caller does work before the guarded write.
- Undo of a delete is now an exact inverse (only the ids IT removed), so a later upload or create survives.
- Share Undo checks patch identity per entity.
- Change template: connections and `description` are kept, and Undo restores the old record and patch (and `typeId`). For seed entities the files come from the base profile.
- FacetSection: every new prop defaults to the old behaviour. The Relationships filter drawer's facets render the same markup apart from the label span's `flex-1`, which stays when there is no `renderBadge`. No Library facet uses it.
- The MixedCheckbox indeterminate state is re-synced from `mixed` on every change, and `aria-checked="mixed"` is present.
- Menu Escape: the synthetic `stopPropagation` stops the native event at the root, so LibraryView's window Escape → clear doesn't fire, and focus goes back to the button. Dialogs opened from the menu restore focus to it through `useFocusTrap`.
- The Timeline Spine's duplicate "Select X" name from the previous review is fixed.
- The selection drawer's O(n²) is fixed (Set-backed `listed`), and `onView` is memoised.
