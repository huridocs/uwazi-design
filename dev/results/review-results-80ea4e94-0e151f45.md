# Review — Results work, playground 80ea4e94..0e151f45

2026-09-21. Read-only review of the full diff plus the code around it. `tsc --noEmit` passes at 0e151f45. No browser run. Findings are ranked by severity; paths are relative to `app/src/`.

## Medium

1. **Best-page ranking counts distinct terms, not satisfied AND groups.** `utils/librarySnippets.ts:659` (the counts are built at :640-656). For `a OR b c`, `terms` = [a, b, c]. A page containing a and b but no c scores termsHit 2, the same as a page containing a and c. The page with a and b matches only the OR side and does not satisfy the query's AND. Hits then break the tie, so the page that misses the AND ranks first when a or b occurs more often on it. Example: `tortura OR tortures desaparición`, where p.12 has tortura×4 and tortures×6 and no desaparición, and p.40 has tortura×1 and desaparición×2. p.12 ranks first. The docblock says an AND query "shows the pages where the terms meet", and it does not in this case. A duplicated term (`a b OR a`, where `highlightTerms` flattens to [a, b, a]) is also counted twice in both `distinct` and `hits`, and the row now prints that total as "N matches". Fix: rank by the number of `groups` that have a term on the page, then by hits.

2. **The source label and the page tag give each row two targets named "Go to page N".** `ResultsMainView.tsx:1097` sets `aria-label={hint}` on `SourceTarget`, so the visible "DOCUMENT" button is announced as "Go to page 15", and the `PageTag` beside it is also "Go to page 15". A screen reader hears the same control twice in a row. The accessible name also drops the visible word, which fails WCAG 2.5.3 Label in Name: a voice-control user who says "click Document" hits nothing. A field row is similar: the visible text is "Country" and the accessible name is "Go to Country", which is acceptable, but "Borrowed document" → "Go to page 15" is not. Either keep the visible label in the name ("Document, go to page 15") or drop one of the two page routes.

3. **The drawer Results tab now re-snippets and reflows during a drawer drag.** `ResultsBody.tsx:103-119`. Before this range, ResultsBody used the fixed `CONTEXT_WORDS`, so a drag changed nothing. Now `ctx` follows the lane width quantised to 64px, and every 64px step of a drag rebuilds `buildSnippetsFor` for up to 40 cards plus every Show-all card, then re-renders them. The excerpt length changes at each step, so the cards change height under the reader and the content above the scroll position moves. That breaks the "never shift layout on state change" rule. The comment at `ResultsMainView.tsx:~188` says the budget "never [changes] mid-drag", but any drag longer than 64px changes it. Quantisation limits how often this happens and does not prevent it. Mount also pays for two full snippet passes (laneW 0 → floor ctx, then the measured ctx). Options: freeze the width while `drawerWidthAtom` is being dragged, or measure on pointerup.

4. **The drawer's PageSpine is now in rank order, while its contract and rail say page order.** `EntityResultCard` gets its snippets from `ResultsBody` with the default `order: "best"`, so the drawer card lists p.47, p.3, p.112 against a spine rail. `search/PageSpine.tsx:9` and `:17` still say "one row per hit page, in page order". "Show all" appends the remaining pages in rank order too. Only `DocumentSearchBody` opted into `order: "page"`. If ranking the drawer card was intended, fix the docs. If not, pass `order: "page"` from ResultsBody.

## Low

5. **Closing AlsoUnder leaves its tooltip stuck on screen.** `AlsoUnder.tsx` together with `Hint.tsx:62`. On close (Escape, choosing an entity, or an outside click on a non-focusable area), `useFocusTrap` returns focus to the trigger. The trigger's `onFocus` → `show` then opens the Hint "Show the N entities with this passage", and it stays until blur, scroll, resize or Escape. After choosing an entity, the hint sits over the row while the entity preview opens beside it.

6. **Hint clamps its centre, not its edges.** `Hint.tsx:79` clamps the centre to [8, innerWidth-8] and then applies `translate(-50%)`. A trigger near a viewport edge puts up to half of the 20rem hint off-screen. Example: the entity button at the pane's inline-start with a long title, "Open Caso Velásquez Rodríguez vs. Honduras" (~260px wide) centred at x≈110, gets clipped by about 20px. In RTL the same happens at the right edge. The hint also never flips below when the trigger is near the top of the viewport.

7. **The Passages footer note counts pages the fold already merged.** `ResultsMainView.tsx:897`. `notShown` is summed per entity. Twelve results that borrow one 81-page judgment fold into its 8 rows, but the note reports 12×73 = 876 "further matching pages". The list is deduplicated and the note is not.

8. **The row highlight can drop when the row's head swaps.** `ResultsMainView.tsx:869-883` together with `rowKey` (~:915). `rowKey` includes `row.entity.id`. If "Show more" loads an own-document result for a passage already folded under a borrowing result, the head swaps and `rowKey` changes. A selection made through the entity button (`activeKey` only, with no `resultsActivePageAtom` write) then goes dark. Selections made with the page tag survive through the `activePage` + `also` fallback.

9. **Title-only matches show a "field" count with no field on the card.** `evidenceBadge` (`utils/librarySnippets.ts:116`) counts `metadata.length`, and that includes the TITLE snippet, which every Results layout drops. A title-only match shows a "1 field" badge on a header-only card, and title + 2 properties shows "3 fields" above a Properties list of 2.

10. **Escape `stopPropagation` in AlsoUnder does nothing.** `AlsoUnder.tsx:53`. The listener is on `window`, so `stopPropagation` there does not stop other `window` keydown listeners (FiltersDrawer, MetadataView, ConfirmDialog…), and `document` listeners (EntityOverlay, Select, ActiveFiltersButton) have already run. Today no other Escape handler coexists with the popover (fill-target skips `role="dialog"`), but the code implies a guarantee it does not give. Use `stopImmediatePropagation` in the capture phase, or remove it.

11. **AlsoUnder position in RTL and on resize.** `AlsoUnder.tsx:40` anchors the popover's left edge to the trigger's left edge in both directions. In RTL, where the trigger sits at the line's end, the list should hang from the trigger's right edge. It is placed once and closes on scroll, but on a window resize or a drawer drag it stays where it was, floating away from the row.

12. **New data with no consumer.** `termsHit[]` (per term: title / properties / documentHits) and `fullTextHits` are computed on every `buildSnippetsFor` call and nothing reads them, according to grep across `src/`. The cost is small (an extra `termIn` per field per term), but the "hit and term counts" API ships with nothing rendering it.

13. **Naming in DocumentSearchBody's PageSpine.** `search/PageSpine.tsx` declares a local `PageTag` that shadows the name of the shared `components/shared/PageTag` and is a different component. Passive rows moved the hit count from `data-part="hits"` to `data-part="page"`, so a "page" part now holds "2×". No selector or test depends on either (checked by grep). Other than that, DocumentSearchBody behaves as before: its order is still page order and its cap and filter are unchanged.

## Checked and clean

- Fold correctness: `docKey|page` merges only passages with the same resolved text. The excerpt is built from the same `ctx` and the same query for every result in one memo, so merged rows cannot differ in text. An entity cannot fold into itself on the CEJIL path, because its pages are unique. The mock corpus keys on text, and self-folding there would need two identical excerpts on different chunks, which is theoretical. Selection through `also` is correct, because an `also` entity's page N is this passage.
- Memo and callback identity: `ResultsBody` is still `memo`'d, `laneRef` is `useCallback([])`, `ctx` is a primitive, and neither ResultsBody nor ResultsMainView adds a new inline prop or object to a memo'd child. `results`/`cappedResults` depend only on primitives plus `entities`.
- ResizeObserver loops: both observers measure the scroll container itself (`getBoundingClientRect` of the `overflow-auto` element), and that width does not change when its own scrollbar appears. No feedback loop.
- Ties: the sort is total (`a.i - b.i`), and the capped and Show-all builds share the same order, so expanding a card does not reorder its first 5.
- Portal cleanup: Hint and AlsoUnder keep their state in the component, so unmounting removes the portal and the listeners. The focus trap restores to a detached trigger when a row unmounts while the popover is open, and focus then falls to body. This is minor.
- Dark mode: `bg-ink text-paper` (inverted hint), `bg-paper border-border`, `hover:bg-parchment`, `bg-vellum` page tag, `ring-carbon/40`. No `var(--x, #hex)` fallbacks. The only raw hex is the existing `#6B7280` type-dot fallback.
- `hidden-by-filters` moved into ListInfoRow's `rightSlot`. It is still always mounted, so ticking a filter shifts nothing. `gap-stack` resolves to `--spacing-stack`.
