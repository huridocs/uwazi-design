## How the checks were judged

PASS only when the Expect was seen in the running app. FAIL carries what was seen against what was expected and a screenshot where one applies. NOT DRIVEABLE names the missing seed data or app state. SKIP is a check whose Needs includes M3 to M9 (schema pending) or `defer`. N/A is an X check that the page's own "Applies:" line excludes. Needs of `—`, F1, F2, F3, F4, M1 and M2 were all driven.

Caveats the groups recorded: every page load logs one Jotai "atomFamily is deprecated" warning, counted as baseline and not as a console failure; the Pages editor preview frame throws a "sandboxed sessionStorage" error that comes from the test harness, ignored; ACT-02 used 101 log entries written straight into sessionStorage; group D regenerated its report from saved results without re-running its nine scripts after its last edits; the app has no failure-injection switch, so every "An error occurred" path is NOT DRIVEABLE (LNG-09, LNG-17, IXE-07, IXE-19, X-04 failure halves). ## FAILs ranked, grouped by likely owner

### Code (behaviour and data)

1. **Content edits do not persist (X-01 FAIL on most content pages).** Lists live in component state or in-memory atoms and are lost on a rail round trip or reload: Menu, Pages list (page text only survives in a session store that a reload clears; deleted pages come back), Languages, Translations (edits discarded on Save), Templates, Thesauri (created or edited thesaurus gone after reload), Uploads (deletions), Preserve, Metadata extraction, Paragraph extraction, Import CSV list. Persisting: Collection, Global CSS & JS, Filters, Users and groups, and (per group E) Relationship types; I did not re-check the last one on this commit.
2. **Pages are not driven by the settings stores or the active data source.** Dashboard stats on Travesía and Artworks show the Sample's 104 entities and do not move when an entity is added; Artworks and Travesía Templates list the Sample's templates; Translations lists a fixed 5 contexts (generated "<name> term N" keys, 6 User Interface keys while the list says 412), ignoring data source and the Menu, Filters and relationship-type contexts; Language install does not reach Translations or any picker.
3. **Activity log and Beacon wording.** `record()` runs with `log:false` on Languages, Translations, Metadata extraction, Paragraph extraction; Templates, Preserve, Uploads, Import CSV and page deletes log nothing; Beacon texts differ from the quoted Uwazi strings ("Profile saved" vs "Account updated", "German installed", "Extractor created", "Library filters updated" vs "Filters saved"). Activity log: seed rows show an invented "Request (example)" line, no before/after fields, no pagination, date range, sort, Clear filters, Export CSV or error/Retry state.
4. **Account and Users flows are missing.** No "Confirm" password modal, no Update/Saved footer, 2FA setup is an inline panel with no secret and accepts any 6 digits, "Reset 2FA" only toasts (jnkemba still Enabled), API keys are not real (no name prompt, no one-time key, Copy writes nothing, reload resurrects revoked keys); Users has no checkboxes, selection bar, bulk actions, Protection column, sorting, Password or User Role field, Invited status.
5. **Validation absent or silent.** Account email accepts "abc"; new-user username has no required/short/long/space rule; no duplicate template-name or property-label check; thesaurus duplicates (name and same-level labels) and empty groups saved or dropped without a message; Filters group names unvalidated; Pages has no required-title rule and the URL field does not follow the title.
6. **Whole features of the spec not built.** Menu (no tree, grips, reorder, Undo), Collection (no favicon, date format, public instance, hide restricted relationships, analytics, forms and email, Global JS flag), Uploads (no import modal, edit, drag and drop, bulk), Preserve still the multi-source editor that Decision G9 removes, Template editor (8 property types of 16, no Title / Date added / Date modified rows, Options pills, Move up/down, row selection, same-label table), Thesaurus editor (no click-to-edit, move to group, sort, collapse all, CSV import and export, virtualisation: "Municipios" renders all 2,443 inputs), Languages (multi-select install, Installing state, CONFIRM-gated Reset), Translations (required-cell validation, per-cell status, per-language progress, Untranslated toggle), Pages (release message, release list, Restore, Configuration tab), Import CSV (Cancel, failure details, row errors, Download failed rows, stepper).
7. **Controls the spec removes are still present.** Metadata extraction per-row Reject, "Accept all", Find suggestions and a Property type select; Paragraph extraction Segmentation, Min characters, Run extraction, Re-run, Last run; Translations "Import translations (CSV)"; relationship-type delete offers "Move references to" (REL-11, against Decision G6 as the checklist reads it; Operator's later decision may supersede).
8. **Role gating.** Collaborator still sees the Library footer "Import CSV" and it opens the New import dialog; no dev panel with a role control or the four feature switches (NAV-01 and dependants); a role that cannot reach the open page gets Account silently instead of "This page is not available."
9. **Failure handling.** When storage writes fail, Pages Save and Publish throw uncaught exceptions, add no "An error occurred" entry and the editor then reads clean (PAG-26).
10. **Discard handling.** The footer Cancel in the user, group, thesaurus, relationship-type and template editors leaves without the guard dialog (X-02 FAIL where the checklist reads Cancel as guarded; F2 treats Cancel as the explicit discard).

1. **Contrast (X-07 and X-08 FAIL on every page with pills).** Light mode: carbon pills 2.08:1 (Default, Editor, System, UPDATE), amber 1.92:1 (Processing, MIGRATE), green 3.32:1 (Ready, Enabled, CREATE, Published); dark mode: green 2.58:1, status pills as low as Error 1.45:1.

4. **Template editor.** The card preview title overlaps the first field label at desktop and phone, light and dark (TED-18); colour control is inline swatches with a native input rather than a picker button and hex field; Save is green where the ladder says commit.
5. **Phone (X-06).** Confirm and discard dialogs open as centred 358px cards with 28px buttons instead of sheets or full screen; rows lack keys and row menus; Pages footer status pill overlaps Discard when dirty; Import CSV Open button 51×27px; Activity log hides user and time until expanded; thesaurus and relationship-type taps do not open the specified sheets.
6. **Dashboard and rail structure.** Cards are Entities, Relationships, Users, Languages (spec Users, Storage, Entities, Files plus Relationships), four across on desktop and two on phone (spec two and one); rail has a "User" heading and an "ML tools" shelf, Uploads and Global CSS & JS sit under Tools (spec Collection), the navbar has Tools plus User and System settings entries (spec one Settings entry).
7. **Copy.** Examples: Account card "Profile" (spec "General Information") with an editable Username; "Template name is required." trailing period; "Label is required." vs "This field is required"; Filters page still says "Types" and has no "Filters configuration" banner; Pages no-match "Nothing matches"; Import CSV labels ("New import", "CSV File") and MM/DD/YYYY dates.
