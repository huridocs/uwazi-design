How it was driven: Playwright (Chromium), one fresh browser context per check group, desktop 1280x800 and phone 390x844 with touch (`open(..., "mobile")`), light and dark (class `dark` on the root element, 900 ms wait for the colour transition, then axe). Scripts: `acceptance-run-2-parts/group-ths-scripts/` (`run-all.sh` re-runs everything, `build.py` writes this file from the `results-*.jsonl` files). Screenshots: `acceptance-run-2-shots/`, named after the check id. Visual looks (light and dark, 1280 and 390) were done on the list and editor of each page; the visual findings that have no check id are in the last section.

Reading the tables:
- PASS only where the Expect was seen. A quoted text that differs from the checklist is a FAIL, except where an amendment (A1, A4) accepts the text as built.
- SKIP: none. No check in these three sections needs M9, `defer` or `drop`. NOT DRIVEABLE: none; every check was driven. Where one clause of a check could not be reached, the row says which (FLT-17).
- Every Dev panel switch was driven: "Fail next request" (Save, Delete, Import or Upload), "Slow load (2 s)", "Empty thesauri", "Empty relationship types", "Empty templates", and "Open thesaurus editor with a missing id". "Slow load", the three "Empty ..." buttons and "Missing id" work on these pages; "Fail next request" is accepted by the panel but no Thesauri, Filters or Relationship types action consumes it, so the next Save, Delete or Import succeeds (THS-37, FLT-12, X-04).
- Console baseline excluded from every check: the Jotai "atomFamily is deprecated" warning, the React `fetchPriority` warning from the catalog's login view (seen only while the Dev panel is open), and pdf.js "TextLayer task cancelled" (seen only in the entity viewer). One error is not excluded: React "Encountered two children with the same key `Judgment`" from `TemplateEditor.tsx` `PropertyRow`, printed every time the Court Case template editor opens. It fails each check that opens that editor (THS-26, FLT-23, FLT-24, REL-02, REL-08, REL-16, REL-18) although their behaviour is as expected; each row says so.
- Phone dialogs: in Playwright's mobile emulation the CSS variable `--kb` is `1189px` right after load (innerHeight 844, visualViewport height 844), so bottom-sheet dialogs measure 1 px high and only the dim overlay shows (THS-38, REL-22, X-06). After a manual `visualViewport` resize event the variable becomes `0px` and the sheet is 227 px high with 44 px buttons. Not confirmed on a physical phone.
- Chromium under the scripts was killed several times during the run (other agents share the machine). The runner starts a script again from its beginning (up to three more times); the results are from complete runs.
- Persistence seen: a tab reload brings back the seed thesauri (THS-09, THS-40, X-01) but keeps new relationship types (REL-05, X-01) and Filters (FLT-02, FLT-07).
